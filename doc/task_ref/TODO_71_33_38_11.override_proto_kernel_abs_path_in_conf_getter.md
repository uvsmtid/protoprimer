Let `get_config` accept an optional `proto_kernel_abs_path` (default `None`) which overrides the module global `_proto_kernel_abs_path`.

## Why

*   [lib_access_to_config_data][UC_54_26_66_63.lib_access_to_config_data.md]:
    `get_config(conf_leap)` returns config data as a function call (without process restarts).

*   It assumes (without verification) that `_proto_kernel_abs_path` (a module global,
    see [context_propagation][FT_96_50_58_75.context_propagation.md]) was set to a stand-alone `proto_kernel.py`.
    There is no way to point `get_config` to a different `proto_kernel.py` per call
    (the check `assert_proto_kernel_is_stand_alone` is disabled with `if False:` because `EnvVar.*` cannot be used,
    see [context_isolation][FT_66_02_54_56.context_isolation.md]).

*   The override mechanism already exists in the context:
    `ContextBuilder.forced_proto_kernel_abs_path(value)` sets `EnvContext._forced_proto_kernel_abs_path`,
    and the state which resolves the `proto_kernel` path prefers it over `get_proto_kernel_abs_path()`.
    `get_config` just does not pass it.

## What to do

*   Add the optional arg `proto_kernel_abs_path: str | None = None` to `get_config` and pass it to the builder
    via `.forced_proto_kernel_abs_path(...)` (only when not `None`).

*   Decide on verification: with an explicit path, `assert_proto_kernel_is_stand_alone` can be applied
    (the global stays unverified as today).

*   Add a test next to `test_get_config.py` (an explicit path overrides the global one; `None` keeps the current behavior).

*   Update [UC_54_26_66_63.lib_access_to_config_data.md][UC_54_26_66_63.lib_access_to_config_data.md] and remove the in-place TODO.

## Considerations

*   Pros: small, backward compatible (the default keeps today's behavior); removes dependence on a process-wide global
    for callers which know the path (e.g. tools working with several clones).

*   Cons / risks: one more way to get inconsistent state if callers mix the global and the override in one process -
    document that the override applies to this call only.
