Fix the naming of `PathName.path_proto_dir` (value `"proto_dir"`) and start using it, or remove it.

## Why

*   `PathName.path_proto_dir` is defined, but (in `primer_kernel.py`) it is not used anywhere else.

*   Its value ends with `dir`, but `dir` is already specified by `FilesystemObject.fs_object_dir`:
    names of fields and states are composed as `<PathName>_<FilesystemObject>_<PathType>`
    (e.g. `field_local_venv_dir_rel_path`), so a `PathName` should not carry its own `dir` suffix.

*   Names of states which refer to the dir of `proto_kernel` use only `PathName.path_proto_kernel`
    (e.g. `state_proto_kernel_updated` - see the naming test `test_name_EnvState.py`) -
    the `proto_dir` is meant to name the parent dir of `proto_kernel` explicitly.

## What to do

*   Pick a suffix-free name for the concept (the dir where [proto_kernel][FT_87_17_49_36.proto_kernel.md] /
    [proto_code][FT_90_65_67_62.proto_code.md] lives) and rename `path_proto_dir`.

*   Use it in the names of states (and fields) instead of using only `path_proto_kernel`
    (update the naming test accordingly), or remove `path_proto_dir` if there is no need.

## Considerations

*   Pros: consistent composition of names; no unused enum member.

*   Cons / risks: renaming states touches tests, docs, and the stand-alone `proto_kernel.py` copy -
    do it together with other state renames
    ([TODO_49_40_51_46.rename_state_names_to_final.md][TODO_49_40_51_46.rename_state_names_to_final.md]).
