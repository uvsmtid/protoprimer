Do not warn about missing config files in the "min scenario" (where there is no config by design) -
but still warn when a config file is required (for some fields).

## Why

*   The "min scenario" has no formal definition under this name. The closest specs are:

    *   [min leaps shape][FT_59_95_81_63.tree_shape.md]: no config dirs and files, only `proto_kernel.py` and `pyproject.toml`, relies on defaults only.

    *   [instant_scenario][FT_21_75_54_18.instant_scenario.md]: no or minimal configuration.

*   Current behavior when a config file is missing (`missing_conf_file_message` via `warn_once_at_state_stride`):

    *   primer conf (`state_primer_conf_file_data_loaded`): warns, uses `{}`.

    *   client/global conf (`state_client_conf_file_data_loaded`): warns, uses `{}`.

    *   env/local conf (`state_env_conf_file_data_loaded`): the warning is disabled (`if False:`), uses `{}`.

*   In the min scenario, the warning is noise - config files are absent on purpose.

*   Existing tests assert the warning for primer and client confs and its absence for the env conf
    (the `metaprimer` has parallel tests and its own copies of the same code and TODO-s in `conf_renderer.py`).

## What to do

*   Define "min scenario" in code (one helper) - not by the absence of one file:
    e.g. it is true when none of the primer, global and local conf files exist.

*   Replace the three unconditional warnings with a conditional one:
    warn when a file is missing but other conf evidence exists (e.g. primer conf exists, client conf is missing).

*   For the local leap, remove `if False:` and warn only when a field which requires the file is actually used.

*   Define what "required for some fields" means.
    Today no field strictly requires a file: all go through `_get_overridden_value_or_default` with a default.
    Candidates: `field_ref_root_dir_rel_path` (has its own warning), env selection fields
    (see [TODO_41_10_50_01.implement_env_selector.md][TODO_41_10_50_01.implement_env_selector.md]
    and [TODO_89_47_85_02.implement_env_selection.md][TODO_89_47_85_02.implement_env_selection.md]).

*   Share the predicate between the kernel and `metaprimer` (`conf_renderer.py`).

*   Tests: keep the "does not exist" assertions for non-min layouts; add a min layout case with no warning
    (e.g. next to the instant scenario tests).

## Considerations

*   Pros: quiet instant scenario; the warning is kept where it carries signal.

*   Cons / risks:

    *   Detecting "min" by the absence of files is heuristic: a typo in a conf path silently runs as min.

    *   State ordering: the primer conf state is evaluated first - check only file paths to avoid cycles between states.

    *   Drift between the kernel, `conf_renderer.py`, and the stand-alone `proto_kernel.py` copy.

*   The hint in the message ("use `op_eval` exec operation for description") is still useful outside the min shape.
