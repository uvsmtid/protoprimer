Check whether the manual clean-up of env vars (`VIRTUAL_ENV`, `PYTHONPATH`, `venv/bin` in `PATH`)
is still necessary after switching to the isolated `python -I` mode.

## Why

*   `Bootstrapper_state_stride_py_arbitrary_reached_is_app` switches out of the current `venv`
    ([run_under_venv][UC_90_98_17_93.run_under_venv.md]) and for that it:

    *   removes `VIRTUAL_ENV` and `PYTHONPATH` from the env;
    *   removes the `<VIRTUAL_ENV>/bin` dir from `PATH`.

*   Later, `switch_python` always starts `python` with `-I`
    ([isolated_python][FT_28_25_63_06.isolated_python.md]).

*   `python -I` ignores `PYTHON*` env vars (so the `PYTHONPATH` clean-up looks redundant for the `python` process itself)
    and the user site dir.
    But it does not change `PATH` and does not touch `VIRTUAL_ENV`.

## What to verify (hypotheses - not confirmed yet)

*   `PYTHONPATH`: redundant for the next `python` (it is `-I`), but it is inherited by child processes
    which do not use `-I` (e.g. tools, shells) - check if any child relies on a clean one.

*   `VIRTUAL_ENV`: not read by `python` itself, but read by other tools (e.g. `uv` uses it to find a `venv`) -
    removing it may still matter for such children.

*   `PATH`: affects lookup of `python`, `uv`, `pip`, ... by children - removing the stale `venv/bin` may still matter.

## What to do

*   For each of the 3 clean-ups, find the child process which would break without it (write a test for it) -
    or conclude it is redundant and remove it.

*   Compare with the generic context isolation: `remove_protoprimer_env_vars`
    ([context_isolation][FT_66_02_54_56.context_isolation.md]) - decide which module owns this clean-up.

*   Remove the in-place TODO (and the clean-up code) or replace it with a comment explaining why each clean-up stays.

## Considerations

*   Pros: less code; the isolation contract is described in one place.

*   Cons / risks: removing the clean-up silently changes behavior for users who start from inside a foreign `venv`
    (a wrong `venv` leaking into children) - integrated tests running from inside a `venv` are needed.
