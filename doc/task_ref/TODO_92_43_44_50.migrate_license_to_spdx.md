## Why

Building any of the packages below with a recent `setuptools` prints `SetuptoolsDeprecationWarning`:

```
`project.license` as a TOML table is deprecated
Please use a simple string containing a SPDX expression for `project.license`.
You can also use `project.license-files`. (Both options available on setuptools>=77.0.0).
By 2027-Feb-18, you need to update your project and remove deprecated calls or your builds will no longer be supported.
```

Where (both packages are published):

*   `src/protoprimer/pyproject.toml`
*   `src/metaprimer/pyproject.toml`

The same warning also says `License ::` classifiers are deprecated
(that is why `License :: OSI Approved :: MIT License` is not listed in `classifiers`).

## Blocker

*   The fix needs `setuptools>=77.0.0` (to be verified: it probably requires `python>=3.9` to run).
*   All projects declare `requires = ["setuptools>=42"]` and `requires-python = ">=3.7"` (see [FT_84_11_73_28.supported_python_versions.md][FT_84_11_73_28.supported_python_versions.md]).
*   Installing a package (including the editable install used by tests) runs its build backend under the interpreter of that environment,
    so the `min` test environment (`python` 3.7) cannot satisfy `setuptools>=77`.
*   A `pyproject.toml` cannot switch between a table and a string by interpreter version.

## Options

*   Wait until the `min` supported `python` is at least the version `setuptools>=77` runs on:
    then set `requires = ["setuptools>=77"]` and `license = "MIT"` in all packages.

*   If the `min` version must stay lower than that by the deadline:
    remove `license` from `pyproject.toml` (no warning, but PyPI loses the license metadata)
    or find another way to publish with a recent `setuptools` (e.g. a separate build environment for `./cmd/publish_package`).

## What to do (once decided)

*   Update both `pyproject.toml` files (and `setuptools` requirement).
*   Run the tests under all `python` versions (`min`, `med`, `max`).
*   Build a wheel and check `METADATA` (`License-Expression`) and that an old `pip` on the `min` version installs it.
*   Remove the in-place `TODO` comments above `license` in both files.
