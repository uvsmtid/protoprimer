Configure `log`, `tmp`, `venv`, ... dirs (and their defaults) at the client level (instead of the env level).

## Why

*   `ConfConstEnv` holds the `default_dir_rel_path_*` constants for these dirs (they are documented as `leap_env` defaults).
    But the layout of dirs is a repo-wide convention (see [reusable_dir][FT_20_13_95_11.reusable_dir.md]):
    it should be the same for all clones and be versioned (under `gconf`).

*   `_get_overridden_value_or_default` already checks the env conf first, then the client conf, then the default.
    So the `ConfField.field_local_*_dir_rel_path` fields are already valid at both leaps -
    only the default constants and `EnvState` naming/placement are env-specific.

*   The default constants are passed directly into `_get_overridden_value_or_default`
    (instead of being resolved at the prev|next step based on the need).

## What to do

*   Decide the contract:
    client conf is the primary source, env conf is an optional override (precedence stays as is),
    the default constants live at the client level (`ConfConstClient`).

*   Move `default_dir_rel_path_*` out of `ConfConstEnv`.

    *   Note: `ConfConstEnv.default_dir_rel_path_venv` is also used as the `venv` sub-command
        in `python -m venv` and `uv venv` calls.
        Split that usage out first (otherwise changing the constant breaks those calls).

*   Resolve defaults once (at the prev|next step) instead of using them directly.

*   Take the `uv.venv` name from config (or a default constant) instead of the hardcoded `"uv.venv"`.

*   Remove the in-place TODO-s: `log, tmp, venv, ... dirs should better be configured at client level` on the `state_local_*_dir_abs_path_inited` states.

*   Make sure `gconf` has values for all of them (`run` and `cache` are not set there now).

## Considerations

*   Pros: single source of truth; fewer scattered defaults; consistent with the reusable dirs spec.

*   Cons / risks:

    *   A clone cannot point `venv` elsewhere (a faster disk or an absolute path) - unless the env override stays (it should).

    *   Moving constants touches many tests and `metaprimer` (`conf_renderer.py`) descriptions.

    *   Precedence change would change behavior for existing clients - keep it as is.

    *   Overlap with [TODO_04_67_81_16.refactor_reusable_dirs.md][TODO_04_67_81_16.refactor_reusable_dirs.md]
        (`cache` -> `gen`, `./var/protoprimer/` layout): both touch `TopDir`, the `default_dir_rel_path_*` constants and the same states.
        Do this first, then the rename and layout change - so the rename touches one location only.
