## Why

`test_fast_not_mocked/test_contract_compatibility/test_parse_args_via_cliff.py` (was `src/local_test/test/test_backward_compatibility/test_CLI/test_via_cliff.py`) is supposed to guard against CLI changes,
but it has gaps (`test_cli_structure_compatibility` compares the real parser against a `cliff` spec):

*   Only `boot`, `reset` and `eval` are compared.
    `start`, `shell` and `wrap` are not in the spec at all - neither are their positional args and options
    (`main_func`, `-c`, `entry_func`, `--entry_script_path`, ...).
    The spec defines `check` which is never compared.

*   Only `dest` of each option is compared.
    `default`, `choices`, `type`, `metavar` (and `required`/`nargs`) are extracted but never compared:
    a changed default or a removed choice passes.

*   Parsers are built via private functions `_create_parent_argparser` and `_create_child_argparser`:
    an internal rename breaks the compatibility test (false positive).

*   Behavior which `cliff` cannot describe is not covered:
    `start` requires `main_func`, args after `--` are target args, `--` is rejected before an operation or with non-`start` operations
    (see `test_parse_args.py` under `protoprimer`).

## What to do

*   Add `start`, `shell` and `wrap` to the spec (`SpecApp`).

*   Exclude `check` from the spec for now: it is not implemented and may change (see `TODO_73_71_31_84.exec_operation_check_or_info.md`).

*   Compare more attributes: `default`, `choices`, `required`, `nargs` (and `type`/`metavar` if they are stable).

*   Use public entry points (`parse_args`) instead of private parser factories where possible.

*   Move behavioral cases from `test_parse_args.py` (`--` rules, required `main_func`, ...)
    next to `test_parse_args_behavior` (already in `test_parse_args_via_cliff.py`) as parametrized rows.

*   Place the result where the contract tests go (see [FT_78_72_23_04.backward_compatibility.md][FT_78_72_23_04.backward_compatibility.md]).
