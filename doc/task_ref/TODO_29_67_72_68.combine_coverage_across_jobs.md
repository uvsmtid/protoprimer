Combine test coverage across all GitHub Actions jobs (not just one `linux` job).

## Why

*   Only `cover.yaml` (`report_coverage`) measures and reports coverage:
    *   it runs on `ubuntu-latest` with `python` 3.15 only;
    *   it uploads to `coveralls.io` (`coverallsapp/github-action@v2`).

*   All other test jobs run tests but report no coverage:
    *   `test_py_min_linux.yaml` (`python` 3.7), `test_py_med_linux.yaml` (3.11), `test_py_max_linux.yaml` (3.15);
    *   `test_py_med_windows.yaml` (3.11 on Windows);
    *   `test_contract_compatibility.yaml` (old tests on new changes, old entry on new proto, ...);
    *   `test_invoke_condition.yaml` (scenarios in containers).

*   So the code which only runs elsewhere looks "uncovered":
    *   Windows-specific branches (`_ConfConstGeneral.is_os_windows`, `subprocess.run` instead of `os.execve`
        in `_switch_python`, `target_is_directory` for `os.symlink`, ...);
    *   `python`-version-specific branches (3.7 compatibility);
    *   scenarios which run in containers (`test_invoke_condition`) or in the baseline worktree (contract tests).

*   `coveralls.io` fails the check on any decrease (observed on PR #194: `coverage/coveralls` -
    "Coverage decreased (-0.05%) to 92.725%"), so partial coverage creates noise.

## What to do

*   Decide the combining approach (one of):
    *   `coveralls.io` parallel builds: each job uploads its own report (`parallel: true` + `flag-name`),
        a final job finishes the build (`parallel-finished: true`);
    *   a final job: each job uploads its `.coverage.*` data as an artifact, the final job downloads all of them,
        runs `coverage combine`, `coverage report` once and uploads the single result.

*   Make the data combinable across OS-es and `python` versions:
    *   `gconf/coveragerc.ini` already has `parallel = true`; add `relative_files = true` and a `[paths]` section
        (Windows vs `linux` checkout paths);
    *   check that the `coverage` versions (3.7 needs an older one than the current `coverage==7.17.2`)
        write compatible data files.

*   Measure the code which runs in other processes or places:
    *   subprocesses started by `test_slow_integrated` (confirm whether `cover.yaml` already captures them);
    *   containers of `test_invoke_condition` (mount or copy the data out);
    *   the baseline worktree of `test_contract_compatibility` (`relative_files` / `[paths]` again).

*   Decide how the check gates PR-s (`fail_under = 80` in `gconf/coveragerc.ini` vs the `coveralls.io` "decrease"
    rule) once the combined number is stable.

## Short-term

*   Adding tests for new lines (done for the env selection nodes on PR #194) only treats the symptom:
    different jobs run different tests on different OS types and `python` versions,
    so combining coverage is required anyway.
*   Platform-specific lines which a `linux` job cannot reach stay uncovered until the combining is in place.
