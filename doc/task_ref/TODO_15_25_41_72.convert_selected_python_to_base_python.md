Instead of restricting `field_selected_python_file_abs_path` (it must not lead to `venv/bin/python`),
convert such a path to its base `python` automatically.

## Why

*   `venv/bin/python` is not an independent interpreter: it belongs to a `venv`
    and (when used to create a new `venv` or to run the bootstrap) leads to the wrong environment.
    That is why the code states a restriction (in `is_venv()`): the selected `python` must be a base one,
    it should be consistent with `sys.base_prefix` - see `get_path_to_base_python`.

*   Today the restriction is on the user: they are expected to configure a base `python` path.
    If they point to `venv/bin/python`, the failure is late and confusing.

*   `get_path_to_base_python()` already derives the base path for the *current* interpreter
    (from `sys.base_prefix` and the basename of `sys.executable`).
    The same conversion is not available for an arbitrary configured path.

## What to do

*   Detect that a configured path points into a `venv`
    (a `pyvenv.cfg` next to or above the executable - the same signal `is_venv()` and `is_uv_venv()` use for the current process).

*   For such a path, resolve its base interpreter (e.g. from `home` in `pyvenv.cfg`, or by running it to read `sys.base_prefix`)
    and use that instead - with a log message (not silently).

*   Decide when conversion is not possible (broken `pyvenv.cfg`, missing interpreter) and fail with a clear message
    (instead of the current restriction note).

*   Remove the in-place TODO and update the docs for the selector fields
    ([python_executable][FT_72_45_12_06.python_executable.md]).

## Considerations

*   Pros: fewer ways to misconfigure; the restriction no longer needs to be remembered by users.

*   Cons / risks: "automatic" conversion may hide a real mistake (the user points to a `venv` on purpose);
    `uv`-created `venv`-s have a different `pyvenv.cfg` layout than `venv`/`pip`-created ones (and a base `python` which `uv` manages);
    run the check also on symlink chains (`venv/bin/python` -> base interpreter).
