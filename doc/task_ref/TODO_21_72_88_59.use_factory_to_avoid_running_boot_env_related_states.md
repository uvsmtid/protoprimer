We have multiple checks like:
```
if state_input_exec_operation_loaded == ExecOperation.op_start:
```

ALl these checks may be avoided by using `Factory_*` which simply does not
use that `Bootstrapper_` for that for that `ExecOperation.*`.
More over, most of these checks really mean "Are we running `boot_env` (with its `reset` variant) or not?".
In other words, what we actually checking there is whether it is `EntryFunc.func_start_app`.

## Analysis

`STANDARD_NOT_BOOT_ENV` means:
> This is a short-circuit not to execute implementation of that `EnvState.*`
> because it is `ExecOperation.op_start` (equivalent of checking for `EntryFunc.func_start_app`).

States that check for `ExecOperation.op_start`:

*   `EnvState.state_prepare_venv_finalized`

    It properly abstracts a `bool` whether to prepare venv.

    `NO_IMPACT`

*   `EnvState.state_func_boot_env_executed`

    This state specifically handles `ExecMode.mode_cli` for `EntryFunc.func_boot_env`.

    Nothing to do.

*   `EnvState.state_stride_py_arbitrary_reached`

    `STANDARD_NOT_BOOT_ENV`

*   `EnvState.state_reset_triggered`

    `STANDARD_NOT_BOOT_ENV`

*   `EnvState.state_venv_driver_prepared`

    `NOOP`: trigger `EnvState.state_input_exec_operation_loaded` only, value is unused.

*   `EnvState.state_stride_py_venv_reached`

    `STANDARD_NOT_BOOT_ENV`

*   `EnvState.state_protoprimer_package_installed`

    `STANDARD_NOT_BOOT_ENV`

*   `EnvState.state_version_constraints_generated`

    `STANDARD_NOT_BOOT_ENV`

*   `EnvState.state_stride_deps_updated_reached`

    `STANDARD_NOT_BOOT_ENV`

*   `EnvState.state_proto_code_updated`

    `STANDARD_NOT_BOOT_ENV`
