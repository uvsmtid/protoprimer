# UC_29_95_32_02.intranet_certs

## Symptom

On an intranet with a TLS-intercepting proxy, `protoprimer` may fail while seeding the `venv`.

When `uv` is configured as [venv_driver][FT_73_95_31_84.venv_driver.md], the failure looks similar to this:

```
error: Failed to install seed packages into virtual environment
  Caused by: No solution found when resolving: `pip`
  Caused by: Failed to fetch: `https://pypi.org/simple/pip/`
  Caused by: error sending request for url (https://pypi.org/simple/pip/)
  Caused by: client error (Connect)
  Caused by: invalid peer certificate: UnknownIssuer

hint: Consider enabling use of system TLS certificates with the `--system-certs` command-line flag
```

## Problem

By default `uv` verifies TLS with its own bundled Mozilla root cert bundle (`webpki-roots`), not the OS trust store.

An intranet proxy that MITM-intercepts HTTPS re-signs traffic with an intranet root CA.

That CA is typically installed in the OS trust store (managed device), but `uv` never looks there by default.

## Solution

Diagnose first:

```sh
curl https://pypi.org/simple/pip/
```

*   If it is a cert error only (connects, TLS fails):

    Then, it is enough to set this env var.

    ```sh
    export UV_SYSTEM_CERTS=1
    ```

*   If it does not connect (proxy blocks `pypi.org` entirely, not just intercepts):

    Then, configure an internal mirror instead:

    ```sh
    export UV_INDEX_URL="https://${internal_mirror}/simple/"
    ```
