# FT_20_13_95_11.reusable_dir

## Description

There is a set of directories used by `protoprimer` which are also reusable by any other tools:

*   `./tmp/` - any temporary data

*   `./log/` - log files

*   `./run/` - runtime state

*   `./gen/` - generated or downloaded data

*   `./venv/` - `python`  virtual env

The only dir `protoprimer` tries to manage is `venv` - all other dirs are reusable.

If external tools want to reuse config for these dirs (without maintaining their own),
they can access to config data via [lib_access_to_config_data][UC_54_26_66_63.lib_access_to_config_data.md].

## Recommendations

*   Many of the dirs above can be grouped under a single parent, for example, `./var/` dir:

    *   `./var/tmp/`
    *   `./var/log/`
    *   ...

    This makes clean up easier (remove `./var/` dir).

*   Even if there is a single parent like `var` dir, it makes sense to keep `venv` outside of it.

    This allows cleaner access to tools via `venv/bin/whatever` path.

*   In the client repo, when the dirs are reused, configure `protoprimer` to use its own space:

    *   `./tmp/protoprimer/`
    *   `./log/protoprimer/`
    *   ...

    This isolates content for different apps.
