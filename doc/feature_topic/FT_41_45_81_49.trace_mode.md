# FT_41_45_81_49.trace_mode

## Why

`protoprimer` restarts `python` multiple times across [state_stride][FT_10_29_17_31.state_stride.md]-s
(via `os.execve`). When debugging execution flow or tracing which lines run across restarts,
standard profilers cannot attach because each restart replaces the process entirely.

`python -m trace --trace` is the stdlib mechanism that traces execution line by line.
Because it is passed as a `python` interpreter flag (not a script argument),
it survives `os.execve` restarts when re-injected at each [switch_python][FT_10_29_17_31.state_stride.md] call.

## How

Set the env var `PROTOPRIMER_TRACE_EXECUTION=true` before running:

```sh
PROTOPRIMER_TRACE_EXECUTION=true ./prime
```

Or enable tracing from the very first `python` invocation to catch bootstrap code:

```sh
PROTOPRIMER_TRACE_EXECUTION=true python -m trace --trace ./prime
```

To capture script output separately from trace output (trace goes to stderr):

```sh
PROTOPRIMER_TRACE_EXECUTION=true python -m trace --trace ./prime 1> stdout.log 2> trace.log
```

### Mechanism

`switch_python` checks `PROTOPRIMER_TRACE_EXECUTION` at each restart.
When `"true"`, it injects `-m trace --trace` into `exec_argv` between the interpreter flag `-I`
and `sys.argv`:

```
python -I -m trace --trace <script> <args...>
```

`sys.argv` inside the running script is always `[script, args...]` — the `-m trace --trace` flags
are interpreter arguments and are not visible in `sys.argv`.
This means each `switch_python` call re-injects them correctly regardless of
how many restarts have already occurred.

The env var propagates across restarts because `switch_python` copies `os.environ`
into `required_environ` before calling `os.execve`.

## Context isolation

`PROTOPRIMER_TRACE_EXECUTION` is a member of [EnvVar][FT_08_92_69_92.env_var.md]
and is removed at [exit_point][FT_07_55_61_77.exit_point.md]-s by `remove_protoprimer_env_vars`.
This prevents the env var from leaking into user code (e.g. `some_main`) or
child processes invoked from [venv_shell][FT_99_89_51_06.venv_shell.md].

See [context_isolation][FT_66_02_54_56.context_isolation.md].

## Caveats

*   Trace output is voluminous. Filter with `grep` or `--ignore-dir` / `--ignore-module` flags.
*   Trace output goes to **stderr**, not stdout. Redirect accordingly.
