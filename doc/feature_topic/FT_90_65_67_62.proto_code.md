# FT_90_65_67_62.proto_code

## What is `proto_code`?

`proto_code` is any code designed to be executed by arbitrary `python` version.

You want to keep `proto_code` to the minimum to avoid complexity because:
*   it has to handle chaotic conditions
*   it is hard to test thoroughly

As much as possible, you want to switch from `proto_code`
to `venv` with pinned dependency versions.

`protoprimer` implements [proto_kernel][FT_87_17_49_36.proto_kernel.md]
which consolidates logic for switching from `proto_code` to `venv`.

## How is `proto_code` started?

User runs one of the [entry_script][FT_75_87_82_46.entry_script.md]-s, for example:

```sh
./start_app_example
```

With `protoprimer`, all such `entry_script` executes is a boilerplate `proto_code`
which invokes [start_app][FT_05_08_64_67.start_app.md] from [proto_kernel][FT_87_17_49_36.proto_kernel.md]
which indirectly invokes a function or a module from `venv` specific to the `entry_script`.
