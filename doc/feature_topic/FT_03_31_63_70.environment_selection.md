# FT_03_31_63_70.environment_selection

## Overview

There are two environment values:

*   persisted

*   selected

## Persistence

[local_env_link][FT_92_51_35_07.local_env_link.md] is the way to persist selected environment.

If there is no `local_env_link`, the environment is not persisted yet.

Each [exec_operation][FT_11_27_29_83.exec_operation.md] can either read or write the persisted environment.

The selection of environment (write) can be done by:

*   `op_boot` = "boot": only if environment is not persisted yet (no `local_env_link`).

*   `op_reset` = "reset": any time to select another environment.

All other `exec_operation`-s only read the persisted environment.

## Selection

When selecting an environment, a special hook (`python` script) is invoked to do it automatically.

It mirrors the [python_executable][FT_72_45_12_06.python_executable.md] selector:

*   imported module in-process (not a subprocess)

*   one function called by name

```python
def select_env_dir_rel_path() -> str | None:
    ...
```

The path to the hook is configured in the `env_selector_file_rel_path` field of `leap_client` [conf_leap][FT_89_41_35_82.conf_leap.md].

For example, this repo uses `src/proto_code/env_selector.py`:
it maps the GitHub job id (`test_py_med_linux`) to the env dir (`dst/test_python_med_linux`).

Outside GitHub Actions, with `CI=true`, it maps the running `python` version and platform to the same env dirs.

The hook can provide:

*   `str` path to the environment config dir (relative to `ref_root`)

*   `None` to select the default environment name

The value provided by the hook is override-able via `--env` CLI arg.

## Default

The default environment name is configured in `leap_client` [conf_leap][FT_89_41_35_82.conf_leap.md].

But the default environment does not affect the result of the selection process,
instead, it provides the environment value to use when persistent value is also absent.

If the default is `None`, global config is used (see [global_vs_local][FT_23_37_64_44.global_vs_local.md]).

## Path

By design, [local_env_link][FT_92_51_35_07.local_env_link.md] is only used as:

*   persistence:

    Store the environment selected to avoid changing it since the last `op_reset`.

*   indication:

    Let all others (outside `protoprimer`) know what is the environment used by that deployment.

Specifically, `protoprimer` itself:

*   should never use path relying on the existence of that symlink

*   instead, it should rely on the value of that symlink to compose direct paths to config data

The direct paths avoid failures for operations like `op_eval` which should work regardless of the symlink presence.

## No environment selected

There can be cases when no environment selected:

*   automatic selection returns `None` (or is not configured)

*   no explicit `--env` CLI arg

In this case:

*   if [local_env_link][FT_92_51_35_07.local_env_link.md] exists, it provides the selection

*   if [local_env_link][FT_92_51_35_07.local_env_link.md] is missing:

    *   if default environment is configured, use it

    *   otherwise, use global config dir (see [global_vs_local][FT_23_37_64_44.global_vs_local.md])

## Conflict

The result difference between selected and persisted environment value depends on:

*   specified `exec_operation`

*   whether environment is already persisted or not (`local_env_link` exists or not)

*   whether the selected environment matches already persisted or not

If selected environment matches the already persisted environment,
this effectively means no override happens
(trivial case, not covered by the table below).

The table below lists outcomes when selected environment does not match persisted environment.

| `exec_operation` | environment persisted? | outcome                             | comment          |
|------------------|------------------------|-------------------------------------|------------------|
| `op_boot`        | yes                    | failure                             | `venv`-dependent |
| `op_boot`        | no                     | select this environment (write)     |                  |
| `op_reset`       | yes                    | select this environment (overwrite) |                  |
| `op_reset`       | no                     | select this environment (write)     |                  |
| `op_start`       | yes                    | failure                             | `venv`-dependent |
| `op_start`       | no                     | failure                             | `venv`-dependent |
| `op_eval`        | yes                    | override                            |                  |
| `op_eval`        | no                     | run                                 |                  |
| `op_shell`       | yes                    | failure                             | `venv`-dependent |
| `op_shell`       | no                     | failure                             | `venv`-dependent |
| `op_check`       | yes                    | TODO                                |                  |
| `op_check`       | no                     | TODO                                |                  |
| `op_wrap`        | yes                    | run                                 | irrelevant       |
| `op_wrap`        | no                     | run                                 | irrelevant       |
