# FT_59_95_81_63.tree_shape

`protoprimer` supports different repo dir tree shapes - from simple to complex.

Essentially, the only difference various dir tree shapes make for `protoprimer` is how it finds all its config.

`protoprimer` uses [conf_leap][FT_89_41_35_82.conf_leap.md]-s to discover configuration:
*   [script_dir][FT_18_38_32_22.script_dir.md] is used to find initial `leap_primer` config
*   [ref_root][FT_51_86_20_81.ref_root.md] is used to find the rest of the configuration

## min leaps shape

This dir tree shape is trivial:
*   no config dirs and files
*   `ref_root`, `script_dir`, and everything else is in `repo_root`

It is a niche use case because it relies on defaults only.

```
^/                                      # repo_root = ref_root = script_dir
│                                       # See:
│                                       # *   FT_51_86_20_81.ref_root.md
│                                       # *   FT_18_38_32_22.script_dir.md
│
├─ proto_kernel.py                      # copy of `protoprimer.primer_kernel`
│                                       # without any config files
│
├─ pyproject.toml                       # `python` project spec for `some_app`
│
├─ some_app.py                          # prod code
├─ test_some_app.py                     # test code
│
└─ ...
```

## max leaps shape

This dir tree shape:
*   separates global and local config - see [global_vs_local][FT_23_37_64_44.global_vs_local.md]
*   employs all [conf_leap][FT_89_41_35_82.conf_leap.md]-s

```
^/                                      # See FT_51_86_20_81.ref_root.md / repo_root
│
├─ proto_code/
│  │
│  ├─ proto_kernel.py                   # proto_kernel = copy of `protoprimer.primer_kernel`
│  ├─ proto_kernel.json                 # See FT_89_41_35_82.conf_leap.md / leap_primer
│  └─ ...
│
├─ script_dir/
│  │
│  ├─ some_script.py
│  └─ ...
│
├─ source_dir/                          # FT_18_38_32_22.script_dir.md
│  │
│  ├─ project_a/                        # one of the `python` projects
│  │  ├─ pyproject.toml
│  │  ├─ main/                          # prod code
│  │  │  └─ project_a/
│  │  │     ├─ __init__.py
│  │  │     └─ some_app.py
│  │  └─ test/                          # test code
│  │     └─ test_project_a/
│  │        └─ test_some_app.py
│  │
│  ├── project_b/                       # one of the `python` projects
│  │   ├─ pyproject.toml
│  │   ├─ main/                         # prod code
│  │   │  └─ project_b/
│  │   │     ├─ __init__.py
│  │   │     └─ some_lib.py
│  │   └─ test/                         # test code
│  │      └─ test_project_b/
│  │         └─ test_some_lib.py
│  │
│  └─ ...
│
├─ conf/                                # See FT_51_86_20_81.ref_root.md / ref_root
│  │
│  ├─ gconf/                            # See FT_23_37_64_44.global_vs_local.md / global_conf
│  │  │
│  │  ├─ proto_kernel.json              # See FT_89_41_35_82.conf_leap.md / leap_client
│  │  └─ ...
│  │
│  ├─ lconf/                            # See FT_23_37_64_44.global_vs_local.md / local_conf
│  │  │                                 # A symlink to (e.g.) ./dst/conf_default/
│  │  │
│  │  ├─ proto_kernel.json              # same as (e.g.) ./env_dir/conf_default/proto_conf.env.json
│  │  └─ ...
│  │
│  ├─ dst/                              # dst ~ destination environments
│  │  │
│  │  ├─ conf_default/
│  │  │  ├─ proto_kernel.json           # See FT_89_41_35_82.conf_leap.md / leap_env
│  │  │  └─ ...
│  │  │
│  │  ├─ conf_special/
│  │  │  ├─ proto_kernel.json           # See FT_89_41_35_82.conf_leap.md / leap_env
│  │  │  └─ ...
│  │  │
│  │  └─ ...
│  └─ ...
└─ ...
```
