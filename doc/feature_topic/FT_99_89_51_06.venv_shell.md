# FT_99_89_51_06.venv_shell

## Problem

One of the common needs is to have a `shell` with activated `venv`.

It is possible to do it manually but inconvenient:
1.  the user has to figure out the path to `venv`
2.  use the `source` command with an arg navigated to `venv/bin/activate`

The path to `venv` may be set across multiple config files (see [conf_leap][FT_89_41_35_82.conf_leap.md]).

## Solution

`protoprimer` CLI provides `shell` sub-command:

```shell
./prime shell
```

## See also

Non-interactive mode: be able to pass an arbitrary command line to be executed by that shell,
or pipe a script to it via `stdin` - both already work with `shell` sub-command.

See [pipe_to_execute_with_activated_venv][UC_36_72_11_12.pipe_to_execute_with_activated_venv.md].

## Implementation

It starts a partial bootstrap process,
specifically to go through the [conf_leap][FT_89_41_35_82.conf_leap.md] until the path to `venv` is identified.

To make start time quicker,
`shell` sub-command skips the `venv` setup - it is assumed to already exist and be up to date.
