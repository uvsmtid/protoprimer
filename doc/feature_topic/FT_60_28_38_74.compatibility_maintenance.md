# FT_60_28_38_74.compatibility_maintenance

## Overview

This doc provides a suggested procedure to update the baseline in case of failures in [backward_compatibility][FT_78_72_23_04.backward_compatibility.md].

## Support branches

`protoprimer` has the following protected branches:
*   trunk branch `main`
*   support branches `support-*`

Normally, `baseline_commit_names` should point to one of the support branches.

## Updating `baseline_commit_names`

One of the expected failures in [backward_compatibility][FT_78_72_23_04.backward_compatibility.md]
are changes in behavior.

In that case, the asserted behavior in one of the `baseline_commit_names` has to be adjusted.

Split each failing test conceptually into scenario (given and when) and outcome (then) parts.
We want to keep the same scenario part, but we want a different outcome (then) part.

## Version-gated outcomes

The baseline tests run against the **new** code (see `old_tests_on_new_changes` in [backward_compatibility][FT_78_72_23_04.backward_compatibility.md]):
the runner installs the current `protoprimer` (editable) into a fresh `venv` with the old tests.

So, a test on the support branch can branch its outcome (then) by the version of the new code:

*   The version is read from the imported `protoprimer`, not from the `pyproject.toml` next to the test
    (that one belongs to the old tree).

*   `local_test.version_gate` does that: it compares the `protoprimer.__version__` of the new code
    (ignoring `.devN` suffixes) with the argument of `@since_version` (inclusive) or `@before_version` (exclusive).

*   Keep the scenario (given and when) in one shared function and add one thin test per outcome (then),
    each gated on the version range:

    ```python
    from local_test.version_gate import since_version, before_version

    def scenario(): ...  # given + when, returns the result

    @before_version("0.15")  # runs for versions below 0.15
    def test_x_before():
        assert scenario() == OLD

    @since_version("0.15")  # runs for versions 0.15 and above
    def test_x_since():
        assert scenario() == NEW
    ```

*   The version must be bumped by the trunk change which changes the behavior:
    otherwise, there is nothing to gate on.

## Procedure

*   Identify which baseline from `baseline_commit_names` fails with the upstream branch.
*   Branch a porting branch from the support branch `support-*` of the `baseline_commit_names` to be fixed.
*   Temporarily set the upstream branch baseline to the porting branch.
*   Apply fixes to both.
*   Merge the porting branch into the support branch.
*   Release the support branch (create a new tag).
*   Change the upstream branch baseline to the new tag.

## Example

*   Trunk branch change (upstream branch): https://github.com/uvsmtid/protoprimer/pull/194

    This provides new tag `0.15.0.dev0` to differentiate new behavior.

*   Support branch change (porting branch): https://github.com/uvsmtid/protoprimer/pull/197

    This provides new tag `0.14.2` to differentiate old behavior.
