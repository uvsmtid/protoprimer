# FT_68_54_41_96.state_dependency

## Intro

There are states and recipes for reaching that state.

This is a similar way how states are "bootstrapped" in other tools, for example:
*   [make][make_wiki]
*   [systemd][systemd_wiki]
*   ...

There is no domain-specific lang used by `protoprime` to define those states (everything is defined via `python` code).

## Identification

Each state is identified by a string (state name).

[proto_code][FT_90_65_67_62.proto_code.md] defines states only
for "proto" phase (see [primer_runtime][FT_14_52_73_23.primer_runtime.md]).

Client code may use that framework to implement client-specific states.

## Dependency: static vs dynamic

States can depend on other states. These dependencies form a directed acyclic graph ([DAG][DAG_wiki]).

It is possible to define single static DAG, but when you have multiple targets,
some of the states will be overloaded with `if/else` conditions
to execute actions for one target and skip action for another target.

To handle multiple targets without overloading state implementation,
`protoprimer` uses [dynamic_DAG][FT_77_15_06_50.dynamic_DAG.md].
