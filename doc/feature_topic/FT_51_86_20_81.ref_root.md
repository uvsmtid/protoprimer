
# FT_51_86_20_81.ref_root

`protoprimer` separates concepts of `repo_root` and `ref_root`:
*   `repo_root` is in its common sense - the root dir of a repo.
*   `ref_root` is a base directory to imply for various relative paths.

`ref_root` may often match `repo_root` but it does not have to.

## `repo_root`

`protoprimer` does not rely on `repo_root` anyhow.

The only reason `repo_root` is mentioned is to explicitly distinguish it from the `ref_root`.

## `ref_root`

The directory inside a user repo that is used as the base to specify most of the relative paths against it.

For many projects, it is natural to suggest that ref root = repo root.
However, it may not always be the case (hence, the different name):
*   some repos may use nested dirs as their `ref_root`
*   in the case of [support_monorepo][UC_94_67_42_40.support_monorepo.md], there can be more than one `ref_root`

The `ref_root` is the central concept for the `protoprimer` where most of the config file paths
are assumed relative to `ref_root` as the base.

See also [script_dir][FT_18_38_32_22.script_dir.md].
