# FT_73_95_31_84.venv_driver

## Description

`venv` driver is the tool user chooses to create and manipulate `venv`.

`protoprimer` supports different `venv` drivers:
*   `pip`
*   `uv`

Depending on the configured `venv` driver:
*   the required `python` version can only be **validated**
*   the required `python` version can be **installed**

Specifically:
*   `uv` can install a missing `python` interpreter itself
*   the standard `python` library `venv` module (used via `pip`) cannot

The driver choice decides:
*   whether `protoprimer` can self-provision the required `python`
*   or whether the environment must already have the required `python`

## Configuration

Set the config field `venv_driver` to one of `VenvDriverType` names:

```json
{
    "venv_driver": "venv_uv"
}
```

*   `venv_uv`  - use `uv` to install `python` and create `venv`.
*   `venv_pip` - use stdlib `venv` + `pip`, no `python` installation.

The default is `uv`.

If `venv_driver` is not specified at all (neither config field nor env var),
`protoprimer` picks the default automatically:
*   `venv_uv` if currently selected `python` is not below `3.8`
*   `venv_pip` if currently selected `python` is below `3.8`

## Behavior

See the difference between **selected** and **required** `python` version in [python_executable][FT_72_45_12_06.python_executable.md].

*   `venv_driver: venv_uv`:

    The selected `python` needs to be `>= 3.8`.

    The selected `python` is only used to download the required `python` version.

    In other words, the selected and required `python` versions do not need to match.

*   `venv_driver: venv_pip`:

    There is no installation step for `python` itself - `pip` can install packages but not interpreters.

    `protoprimer` runs `python -m venv` directly with the selected `python`, then seeds it via `pip install --upgrade`.

    The selected `python` version must already be the required `python` version.

    If `protoprimer` cannot find the required `python` version on the system (e.g. via `PATH`), it fails.
