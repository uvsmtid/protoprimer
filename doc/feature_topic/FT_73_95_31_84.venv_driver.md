# FT_73_95_31_84.venv_driver

## Description

`venv` driver is required because the tool used to create the `venv` determines
whether the required `python` version is *installed* or only *validated*.

`uv` can install a missing `python` interpreter itself; the stdlib `venv` module (used via `pip`) cannot -
it only ever uses whatever `python` executable it is given.

The driver choice is therefore not cosmetic: it decides whether `protoprimer` can self-provision
the required `python`, or whether the environment must already have it
(see [python_executable][FT_72_45_12_06.python_executable.md]).

## Configuration

Set the config field `venv_driver` to one of `VenvDriverType` names:

```json
{
    "venv_driver": "venv_uv"
}
```

*   `venv_uv` (default) - use `uv` to install `python` and create `venv`.
*   `venv_pip` - use stdlib `venv` + `pip`, no `python` installation.

Override without touching config via env var:

```sh
export PROTOPRIMER_VENV_DRIVER=venv_pip
```

If `venv_driver` is not specified at all (neither config field nor env var),
`protoprimer` picks the default automatically:
`venv_uv`, unless the currently selected `python` is below `3.8`
(the minimum `uv` itself requires to run) - then it falls back to `venv_pip`.
An explicit `venv_driver` value is always honored as-is, regardless of the selected `python` version.

## Behavior

*   `venv_driver: venv_uv`:

    The selected `python` (see [python_executable][FT_72_45_12_06.python_executable.md]) only needs to be `>= 3.8` -
    it is used solely to bootstrap `uv` itself into a throwaway `venv`.

    `uv` then runs `uv python install <required_python_version>` to guarantee the exact required interpreter
    is present, regardless of what was selected, then `uv venv --seed ...` to create the final `venv` with it.

    Selected and required `python` versions do not need to match beforehand.

*   `venv_driver: venv_pip`:

    There is no installation step for `python` itself - `pip` can install packages, never interpreters.

    `protoprimer` runs `python -m venv` directly with the selected `python`, then seeds it via `pip install --upgrade`.

    The selected `python` must already be the required version;
    if no matching interpreter is found on the system (e.g. via `PATH` or a [python selector][FT_72_45_12_06.python_executable.md]),
    bootstrap fails - there is no fallback to obtain it.
