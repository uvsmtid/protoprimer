# FT_30_24_95_65.state_idempotency

Each state value is treated as idempotent (re-evaluation/re-bootstrapping of state value must yield the same value).

Because of that (for optimization), the evaluated value may be cached.

Even witch cached values, the idempotency must be ensured because `proto_kernel` re-starts itself using
a different [python_executable][FT_72_45_12_06.python_executable.md] which invalidates cached values.

If the state has to have different values evaluated for different moments within [bootstrap_process][FT_57_87_94_94.bootstrap_process.md],
this has to be different states (different names) each producing its own value.
