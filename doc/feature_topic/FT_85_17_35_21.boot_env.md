# FT_85_17_35_21.boot_env

This article describes how `protoprimer` can be used to bootstrap an environment.

During this function, `protoprimer`:
*   Downloads the required `python` version.
*   Creates `venv`.
*   Populates `venv` with dependencies.
*   Passes control to custom client bootstrap steps.

The case is indicated by `EntryFunc.func_boot_env` (see [entry_func][FT_25_62_13_55.entry_func.md]).

## Custom setup

There are two ways to implement custom bootstrap steps:

*   `run_boot_env_client_func(client_func)` - for a plain function call.

*   `ContextBuilder` - for extending the DAG with custom `StateNode`-s depending on `EnvState.*`
    (see [extend_DAG][UC_10_80_27_57.extend_DAG.md]).

See also [boot_vs_start][FT_58_74_37_70.boot_vs_start.md].
