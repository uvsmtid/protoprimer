# FT_05_08_64_67.start_app

This article describes how `protoprimer` can be used to start an application.

During this function, `protoprimer`:
*   Assumes `venv` is prepared.
*   Switches to the required `python`.
*   Starts custom client `main` function.

Specifically, it avoids populating the `venv` or downloading the required `python` version.

The case is indicated by `_EntryFunc.func_start_app` (see [entry_func][FT_25_62_13_55.entry_func.md]).

## Args for the target function

The `start` sub-command (`_ExecOperation.op_start`) passes the args after a literal `--` to the target function
(like `entry_script` does for free as a separate process):

*   Why the same process needs it:

    Otherwise `sys.argv` leaks own tokens of `protoprimer` or drops the args of the user.

*   Why `--`, not `argparse.REMAINDER`:

    It would swallow its own flags of `protoprimer` (e.g. `start m:f -v`).

*   Why an error for `--` with other exec operations:

    Args must not be silently discarded.

*   Why it chains:

    `main_func` can be `_proto_main` itself, so each `--` unwraps one level.

See also [boot_vs_start][FT_58_74_37_70.boot_vs_start.md].
