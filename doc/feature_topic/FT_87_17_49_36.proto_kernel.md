# FT_87_17_49_36.proto_kernel

## What is `proto_kernel`?

`proto_kernel` is a **copy** of `protoprimer.primer_kernel` module
stored **together** with the client code in the target client repo.

## `proto_kernel` vs `primer_kernel`

The 2 are nearly identical but intentionally distinct:

*   `proto_kernel` is a **copy** of `protoprimer.primer_kernel` module.

    The actual file name `proto_kernel.py` is the default (but can be almost anything).

*   `primer_kernel` is intentionally different from `proto_kernel.py` (to avoid confusing `import`-s).

Only a **single** own copy of [`proto_kernel.py`][local_proto_kernel.py]
is needed per repo to be used by all [entry_script][FT_75_87_82_46.entry_script.md]-s.

The `proto_kernel` for this repo is stored at:

```sh
./cmd/proto_code/proto_kernel.py
```

With some config, the copy can be moved (under any directory, under any name).

Although it is possible to run the copy directly, it is more flexible to use entry scripts (wrappers):

*   `entry_script` [`./prime`][local_prime] relies on the `boot_env` function (to prepare the `venv`).

*   `entry_script`-s in the [`./cmd`][cmd_dir] dir mostly rely on the `start_app` function (to start code from the `venv`).

## How is `proto_kernel` updated?

Specifically, for this repo, any changes to `protoprimer.primer_kernel`:

```
./src/protoprimer/main/protoprimer/primer_kernel.py
```

will be automatically reflected in `proto_kernel`:

```
./cmd/proto_code/proto_kernel.py
```

after running bootstrap via:

```sh
./prime
```
